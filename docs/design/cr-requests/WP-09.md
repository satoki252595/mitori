# WP-09 — change requests (server + client, 2026-10-03)

Implementation notes for the integrator are at the end. Everything below is a proposal; the code carries a local
workaround marked `CR-PENDING(WP-09)` where one was needed.

## Lock-file port for the daemon lock
- contract: `packages/server/src/contract.ts` — `ServerDeps` (and a platform `lock/` contract, WP-01)
- change:
  ```ts
  /** O_CREAT|O_EXCL lock files (`~/.mitori/daemon.lock`). */
  export interface LockFilePort {
    tryCreate(path: string, content: string): boolean; // false when it exists
    read(path: string): string | null;
    remove(path: string): void;
  }
  // ServerDeps
  lock: LockFilePort;
  ```
- why: server spec §1.1 (a) needs `O_CREAT|O_EXCL`; the server may not write files directly (boundary checker) and
  `SafeWriter` has no exclusive-create. WP-01 lists "lockfile" as a deliverable but no contract names it.
- workaround in place: `LockFilePort` is declared locally in `packages/server/src/http/lock.ts` (`CR-PENDING(WP-09)`);
  `startDaemon` (`http/daemon.ts`) takes it as an option. Tests adapt `writeFileSync(path, c, { flag: "wx" })`.
- urgency: blocks wiring `createServer` (WP-INT) to the real lock.

## `ServerDeps.version` (and the daemon PID)
- contract: `ServerDeps`
- change: `version: string` (mitori semver; `HealthRes.version`, registry, `hello.version`). Optional `pid: number`
  (default `process.pid`) keeps tests deterministic.
- why: nothing in `ServerDeps` carries the version; it lives in `apps/cli/package.json`.
- workaround in place: `startDaemon({ version, pid, … })` takes both; WP-INT passes them through.
- urgency: blocks `createServer`.

## `createServer` when another daemon already holds the lock
- contract: `createServer(deps): Promise<ServerHandle>`
- change: document the outcome when the lock is held by a live, healthy daemon — e.g. reject with
  `MitoriError("E_PRECONDITION", …, { params: { pid, port } })` — so `mitori _serve` exits 0 quietly.
- why: `startDaemon` returns `{ kind: "running", holder }` in that case (SRV-I-023); `ServerHandle` cannot express it.
- workaround in place: none needed inside WP-09; WP-INT maps it.
- urgency: before WP-11 `_serve`.

## Export the CLI-side health probe
- contract: `packages/client/src/contract.ts`
- change:
  ```ts
  /** Verified health of a daemon (proof = HMAC-SHA256(token, challenge)) or null; never sends the token. */
  export declare function probeDaemon(opts: { origin: string; token: string; challenge: Uint8Array; fetch?: typeof fetch; timeoutMs?: number }): Promise<HealthRes | null>;
  ```
  (alternative: `ClientOptions.random?` and `createApiClient` verifies once before its first bearer request.)
- why: SEC-06 / SRV-I-028 / SRV-AT-09 — the CLI, MCP shim and hooks must check `proof` before sending the bearer.
  The implementation exists (`packages/client/src/http/probe.ts`, WebCrypto, isomorphic) but sub-directory index files
  may only export contract names.
- workaround in place: `probe.ts` is internal (`CR-PENDING(WP-09)`), tested in `http/http.test.ts`.
- urgency: before WP-11 talks to a real daemon.

## Typed access to the estimate of a 409
- contract: `packages/client/src/contract.ts` — `ApiClient.call` error type
- change: e.g. `export interface ApiCallError extends MitoriError { estimate?: JobEstimate | GenEstimate }`.

- urgency: nice to have (WP-10b reads it).

## Notes for the integrator (no contract change)
- `startDaemon(opts)` (`packages/server/src/http/daemon.ts`) is the daemon lifecycle: lock → `openState()` (state
  migrations applied by the caller, `migrationsFor("state")`) → session key → services → port (`srv_ports` first) →
  registry → idle exit. It returns `{ kind: "started", daemon }` with `daemon.services` (hub, sessions, trust,
  workspaces, settings …), `daemon.app` and `daemon.stop(reason)`.
- Server migrations: `SERVER_STATE_MIGRATIONS` / `SERVER_WORKSPACE_MIGRATIONS` in `http/schema.ts` (for
  `migrationsFor`).
- Domain route adapters plug in as `handlers: RouteHandlers` (`routes/types.ts`); any route without a handler answers
  501. Domain-derived parts of server routes plug in as `domain: DomainProviders` (`routes/services.ts`: status, git,
  init, inbox, sectionOf).
- Workspaces: `workspace.assemble(base)` builds the domain parts (`ws/manager.ts` `WorkspaceParts`); the manager
  calls `doc.load()`, runs `indexer.scan({reason:"open"})` in the background and calls `parts.start()` (watcher +
  index.delta wiring) after the first successful scan. `rescan(ws, force)` is the way out of `error`.
- `POST /ws/:ws/touch` for an unregistered key is answered by the pipeline (`{staleBlocks:0, registered:false}`)
  before any loop handler runs (SRV-I-031).
- `ws/queue.ts` exports `guardMutators(target, methods, queue)` / `assertInWriteSlot` for the dev assertion on
  DocStore / ReviewEngine / JobRunner mutators (server spec §3.1).
- Watch `~/.mitori/config.json` and call `settings.reload()` (`notice.settings.reloaded`); our own writes do not
  re-trigger (content comparison).
