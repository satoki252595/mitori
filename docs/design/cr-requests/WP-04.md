# WP-04 — change requests (doc, 2026-10-03)

Requests first (contract gaps with a `CR-PENDING(WP-04)` workaround), then notes the architect / spec owners should
know (no contract change needed).

## `createDocStore` needs a read-only filesystem
- contract: `packages/doc/src/contract.ts` A4 / `packages/doc/src/store/index.ts` — `createDocStore(deps)`
- change: `fs: FsReader;` in the deps (core `FsReader`).
- why: `load()` (§10.4) reads `<docDir>/**`, the ownership ledger (ADR-0004 R1 §4, SEC-02) has to `stat`/read a file
  before overwriting it, and docDir validation (RT-25) needs `lstat`/`realpath`. Without it `load()` has nothing to
  read and the ledger cannot detect foreign bytes.
- workaround in place: optional `fs?: FsReader` read from the deps object (`store/core.ts` `StoreDeps`,
  `store/index.ts` doc comment). Without it `load()` returns an empty report and the ledger check is skipped.
- urgency: blocks WP-INT wiring of the real store (the acceptance tests pass `fs`).

## `createDocStore` needs a timer port for the flush cadence
- contract: same function.
- change: `timers?: { setTimeout(fn: () => void, ms: number): unknown; clearTimeout(id: unknown): void };` (testkit
  `FakeClock` already has this shape).
- why: §10.9 / PT-11 — flush 500 ms after a change, 2 s while generating, cite-only moves after 10 s of quiet. `Clock`
  has no timers; DOC-U-018 asks for a FakeClock test.
- workaround in place: optional `timers` (falls back to an unref'ed global `setTimeout`; `null` disables auto-flush).
- urgency: nice to have (the fallback works in production).

## `GenIdSource.next` cannot mint a `doc_` id (nor `dg_`)
- contract: `packages/doc/src/contract.ts` A5 — `GenIdSource.next(kind)`
- change: add `"doc"` and `"diagram"` to the kind union.
- why: `ensureManifest()` mints `docId` (CONS-11); AI diagram blocks need a diagram id.
- workaround in place: `store/apply.ts` `ensureManifest` derives `doc_` + base32(sha256(ws.key ‖ clock.iso ‖
  ids.next("block")))[:12] (or uses `ws.docId`); diagram ids are `dg_` + base32(xxh3(docId ‖ slot or block id)) —
  deterministic under seeded ids and a fake clock.
- urgency: nice to have.

## `StaticDocInput.estimates` (placeholder label 「生成する ≈N tok」, `SectionNode.est`)
- contract: `packages/doc/src/contract.ts` A4 — `StaticDocInput`
- change: `estimates?: Partial<Record<SectionId, { inTokens: number; outTokens: number }>>;` (gen planner numbers).
- why: MILESTONES WP-04 / DOC-U-015 — the §6 placeholder shows 「生成する ≈6k tok」 and N must equal the estimate; CR
  ux-R14 added `SectionNode.est` but nothing feeds it to the store. Doc cannot import gen.
- workaround in place: `store/apply.ts` `applyStatic` reads an optional `estimates` property from the input object;
  without it the label has no number.
- urgency: before M2 (gen wiring).

## `STATIC_SLOTS` lacks the section placeholder slot
- contract: `packages/doc/src/contract.ts` A2 — `STATIC_SLOTS`
- change: add `"<section>:ph"` (as `m:<id>:ph` exists for modules).
- why: §1, §3, §9 … have no static content but must not render empty (DOC_TEMPLATE comment); their placeholder needs
  a deterministic slot.
- workaround in place: the store uses `<section>:ph` already.
- urgency: nice to have (documentation of the slot list).

## `toMarkerForm(md, lang)` cannot resolve cite paths
- contract: `packages/doc/src/contract.ts` A3 — `toMarkerForm`, `CiteLinkGroup.cites[].path: RepoPath`
- change: `toMarkerForm(md: string, lang: DocLang, ctx?: CodecContext)`; without `ctx` the path is the href path.
- why: hrefs are relative to the doc file (§10.3); turning them into RepoPaths needs `docFile`, `docDirAbs`,
  `rootAbs`. `parseDocFile` has the context and resolves them; `toMarkerForm` alone cannot.
- workaround in place: without a context `path` is the decoded href path as written (documented on the function);
  `parseDocFile` returns resolved RepoPaths.
- urgency: nice to have.

## SafeWriter must be able to create the doc root (WP-01)
- contract: core `SafeWriter` / platform `SAFE_WRITE_RULES` (kind `doc`)
- change: for kind `doc`, create `rootReal` itself when missing, after checking that its parent chain is a realpath
  (or add `ensureRoot(rootReal, kind)`).
- why: the doc store passes `rootReal = <root>/.mitori` (validated: inside the repo, not the root, no symlink in the
  existing part — RT-25/27/29). On a first run that directory does not exist, so "rootReal is itself a realpath"
  cannot hold yet.
- workaround in place: none in production code; the test SafeWriter (`src/test/helpers.ts` `spySafeWriter`) creates
  the root when its parent is a realpath.
- urgency: blocks the first write on a fresh repo once WP-01's SafeWriter is wired.

## Export the worker-side halves of highlighting and ELK layout
- contract: `packages/doc/src/contract.ts` A4 (new names) — consumed by WP-INT's compute / ELK worker entries
- change: export `createHighlight(wasm): Promise<(req: HighlightReq) => string>` (render/shiki.ts) and
  `elkLayout(elk, { ir }): Promise<DiagramLayout>` (layout/elk.ts).
- why: the contract pools are `WorkerPool<HighlightReq, string>` and `WorkerPool<{ ir: DiagramIR … }, DiagramLayout>`,
  so the IR → ELK conversion and Shiki tokenization run inside the workers. The skeleton's ELK pool
  (`apps/cli/src/daemon/elk.ts`) takes ELK JSON instead. Sub-directory index files may export contract names only,
  so these cannot be imported today.
- workaround in place: implemented in sibling files and used by the doc tests (in-thread pools / a real ELK Worker).
- urgency: blocks WP-INT wiring of highlighting and layout.

## A way to get a block's Markdown line (`BlockView.mdLine`, `data-ln`) and the glossary first use

- change: `DocStore.mdLine(id: BlockId): number` (1-based line of the block in its file, from the serializer); the
  renderer would need the doc-wide first use of a term for `data-first` (e.g. `glossaryTerms: Map<term, { id; first:

- workaround in place: none (`render()` returns the body; the `.mb` root with `data-ln` is the server's).
- urgency: before WP-10a's permalinks.

## `HighlightReq.lang` cannot name json / yaml / sh / sql

## Notes (no contract change)

- **O8 byte rules (frozen with WP-04, `codec/parse.ts` / `codec/wrap.ts`)**: blocks in order, exactly one blank line
  between blocks, one trailing LF, NFC outside code. `trailing` kinds end with ` <!-- b_… -->` on their last line
  (trailing spaces removed first); `own_line` kinds — and any block whose last line is inside a code block — get the
  comment alone on the next line. Heading md keeps its `#` marks (the level is not in `BlockMeta`); code and diagram
  md keep the whole fence (the diagram md is caption + blank line + the `toMermaid` fence); question md excludes the
  `- `; alert kinds are unwrapped exactly (`>` for blank lines) or kept verbatim as prose. Parsing never loses text:
  text before a block that fits no wrapper and text after the last comment become new human blocks; an ID comment
  must end its line (anything after it makes it text), ID-like comments in code are text, alphabet violations are
  text. All 20 `doc-roundtrip` documents round-trip byte-identically through the codec and the store.
- **GitHub rendering**: the comments are HTML comments (inline for trailing, a type-2 HTML block for own-line), so
  GitHub hides them; own-line comments end lists/tables because an HTML block interrupts them. Verified with GitHub's
  renderer: `docs/design/specs/assets/wp04-github/` (sample, rendered HTML, checks, screenshot) — please link it from
  gen spec §10.2.
- **Ownership ledger**: `doc_files(rel, digest, size, mtime_ns)`. The digest is xxh3 (the ledger needs equality only)
  and is omitted above 1 MB — hashing an 18 MB sidecar costs ≈ 3 ms per flush, the bench budget is 5 ms. A
  stat mismatch on a digest-less file counts as foreign (Markdown / sidecar ⇒ imported by the next `load()`).
- **Sidecar sharding (REVIEW-LOG R1-O6)** is not needed: the bucketed fragment memo keeps the 1-block flush of a
  10k-block doc (18.7 MB sidecar) at 2.7 ms CPU / 2.5 ms wall with an in-memory writer (the real SafeWriter adds the
  UTF-8 encode + write of the sidecar to the wall time).
- **Perf measurements** live in `packages/doc/src/test/perf/perf.test.ts` (`MITORI_PERF=1 scripts/nd bun test
  packages/doc/src/test/perf`): render 2,000 blocks cold 54 ms / cached 2.8 ms, ELK 300 nodes 54 ms / 1,000 nodes
  ≈ 190 ms (real ELK Worker), flush as above. `bench/budgets/doc.json` still names `bench/doc.bench.ts` (WP-12's
  runner) as the measure; point it here or wrap these cases when the runner lands.
- **Write queue**: `editBlock` stamps outside the queue and enters it itself (call it outside `write()`); `flush`
  never enters the queue (flushes are serialized internally), so it can be reserved inside a slot (CONS-36);
  `load()` may run inside a slot (file reads only) and re-stamps imported cites in a later slot.
- **Events**: the store emits `doc.saved`, `doc.outline`, `doc.block.removed`, `doc.freshness`, `doc.claims`,
  `doc.proposal.removed`, `notice`. `doc.block.upsert` / `doc.proposal.upsert` carry rendered views, so the server
  emits them (from `ApplyResult` / the returned blocks).
- **Verdicts**: the store follows the core `Verdict` doc (L1 fail ⇒ `unsupported`, L1 vacuous ⇒ `cited`), which
  differs from gen spec §7.2 row 5.
- **ELK**: groups are laid out bottom-up (`SEPARATE_CHILDREN`); an edge between groups is an aggregated edge between
  the groups for layering and is drawn as a straight connector between the two boxes (`INCLUDE_CHILDREN` costs ≈ 10×:
  1,000 grouped nodes 1.6 s). Measured: 300 nodes 54 ms, 1,000 nodes 184 ms.
- **editBlock and UXP-20**: the store saves and returns `dropped`; the server's "出典が外れます" first step needs a
  preview — comparing `toMarkerForm` link groups with `claims(id)` by cite set gives the same answer.
