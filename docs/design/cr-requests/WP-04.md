## `createDocStore` needs a read-only filesystem
- contract: `packages/doc/src/contract.ts` A4 / `packages/doc/src/store/index.ts` — `createDocStore(deps)`
- change: `fs: FsReader;` in the deps (core `FsReader`).
- why: `load()` (§10.4) reads `<docDir>/**`, the ownership ledger (ADR-0004 R1 §4, SEC-02) has to `stat`/read a file
  before overwriting it, and docDir validation (RT-25) needs `lstat`/`realpath`. Without it `load()` has nothing to
  read and the ledger cannot detect foreign bytes.
- workaround in place: optional `fs?: FsReader` read from the deps object (`store/core.ts` `StoreDeps`,
  `store/index.ts` doc comment). Without it `load()` returns an empty report and the ledger check is skipped.
- urgency: blocks WP-INT wiring of the real store (the acceptance tests pass `fs`).

## `createDocStore` needs a timer port for the flush cadence
- contract: same function.
- change: `timers?: { setTimeout(fn: () => void, ms: number): unknown; clearTimeout(id: unknown): void };` (testkit
  `FakeClock` already has this shape).
- why: §10.9 / PT-11 — flush 500 ms after a change, 2 s while generating, cite-only moves after 10 s of quiet. `Clock`
  has no timers; DOC-U-018 asks for a FakeClock test.
- workaround in place: optional `timers` (falls back to an unref'ed global `setTimeout`; `null` disables auto-flush).
- urgency: nice to have (the fallback works in production).

## `GenIdSource.next` cannot mint a `doc_` id (nor `dg_`)

- urgency: nice to have.

## Findings of the WP-04 verification (2026-10-03) the architect should decide

- **DOC-B-001 with real I/O (REVIEW-LOG R1-O6 trigger)**: the 5 ms CPU target holds for the flush itself (serialize +
  bookkeeping: 2.7–3.5 ms with an in-memory writer, `perf.test.ts`). With the node-fs writer the same 1-block flush of
  the 10k-block doc costs ≈ 8–10 ms CPU, because the 18.7 MB sidecar is UTF-8-encoded and written on every flush
  (writing 21 MB costs ≈ 2 ms CPU alone; the rest is the encode copy and the GC of the 18 MB string). With WP-01's
  fsync the wall time will also pass the 20 ms limit on macOS. R1-O6 says "shard when the 10k bench exceeds 5 ms":
  sharding `doc.index.json` per doc file (e.g. `index/<file>.json` + a small root) bounds a 1-block flush by the size of
  one file's shard. It is a format change (ADR-0004 R1 names one `doc.index.json`; ADR-0014's `doc` allowlist has no
  shard paths), so it is the architect's call; the store's bucketed memo already renders per bucket, so shards map onto
  it directly.
- **ELK on real dependency graphs**: the synthetic 1.5 edges/node graphs meet the budget (300 ≈ 52 ms, 1,000 ≈ 180–
  205 ms). File-level import graphs of the corpus (top-300 / top-1,000 files by degree of excalidraw and react,
  grouped by directory, ≈ 5 edges/node) take 300 nodes 109–126 ms (target 100, limit 150) and 1,000 nodes 243 ms; flat
  (ungrouped) 148–325 ms / 368–433 ms. `elk.layered.crossingMinimization.strategy: NONE` brings the grouped 300 to 61–
  77 ms and 1,000 to 135 ms at a visible quality cost (more crossings); not applied. Options: accept for `GraphView`
  file level, cap the file-level graph, or switch crossing minimization off above a density threshold.
- **Proposal cites are not re-anchored while pending**: a proposal's md carries cite links as of its creation. If the
  code moves before the human accepts it, the accepted links point at the old lines (stamped by the stamper at the
  current snapshot, or with the proposal's old stamp, which the anchor engine re-anchors by blob). Re-anchoring pending
  proposals (or stamping them at creation and re-anchoring on accept) belongs to anchor/loop.
- **Missing static slot**: `s11:large` (大きいファイル表, gen §4.1) needs per-file sizes, which `StaticDocInput` does not carry
  (only per-module `loc`); not produced.

## Notes (no contract change)

- **O8 byte rules (frozen with WP-04, `codec/parse.ts` / `codec/wrap.ts`)**: blocks in order, exactly one blank line
  between blocks, one trailing LF, NFC outside code. `trailing` kinds end with ` <!-- b_… -->` on their last line
  (trailing spaces removed first); `own_line` kinds — and any block whose last line is inside a code block, or whose
  last line would become code with the comment appended — get the comment alone on the next line. Cite labels escape
  Markdown punctuation (`]` as `&#93;`, which `groupRe` forbids; `\_`, `\|` …); hrefs percent-encode `% ()#|`.
  On load the store passes the sidecar kind: a known block owns its whole segment (own-line kinds, prose, list, and a
  heading with text after it), so every block the store writes reads back as itself (seeded property test
  `codec/roundtrip.property.test.ts`); shape inference and new human blocks apply to unknown ids and to text before a
  heading or an alert. Heading md keeps its `#` marks (the level is not in `BlockMeta`); code and diagram
  md keep the whole fence (the diagram md is caption + blank line + the `toMermaid` fence); question md excludes the
  `- `; alert kinds are unwrapped exactly (`>` for blank lines) or kept verbatim as prose. Parsing never loses text:
  text before a block that fits no wrapper and text after the last comment become new human blocks; an ID comment
  must end its line (anything after it makes it text), ID-like comments in code are text, alphabet violations are
  text. All 20 `doc-roundtrip` documents round-trip byte-identically through the codec and the store.
- **GitHub rendering**: the comments are HTML comments (inline for trailing, a type-2 HTML block for own-line), so
  GitHub hides them; own-line comments end lists/tables because an HTML block interrupts them. Verified with GitHub's
  renderer: `docs/design/specs/assets/wp04-github/` (sample, rendered HTML, checks, screenshot) — please link it from
  gen spec §10.2.
- **Ownership ledger**: `doc_files(rel, digest, size, mtime_ns)`. The digest is xxh3 (the ledger needs equality only)
  and is omitted above 1 MB — hashing an 18 MB sidecar costs ≈ 3 ms per flush, the bench budget is 5 ms. On a stat
  mismatch the file is read: bytes equal to what the store last wrote or read are ours (a `touch` / checkout), anything
  else is foreign (Markdown / sidecar ⇒ imported by the next `load()`, never overwritten).
- **Reload = block-level 3-way**: `load()` after the first compares each block on disk with the text the store last
  wrote (or read) for that file: an untouched block keeps the model's text (an unflushed generated / static change),
  a block the model has not written yet is kept in place, an unflushed deletion stays deleted, id-less text already in
  the base is not imported twice. A reload that sees only our own writes is a no-op (no `doc.outline`).
- **Sidecar sharding (REVIEW-LOG R1-O6)**: see the findings above (in-memory 2.7–3.5 ms CPU; with real I/O ≈ 8–10 ms).
- **Perf measurements** live in `packages/doc/src/test/perf/perf.test.ts` (`MITORI_PERF=1 scripts/nd bun test
  packages/doc/src/test/perf`): render 2,000 blocks cold 52–62 ms / cached 2.7 ms, Shiki 100 lines ≈ 4.3 ms, ELK 300
  nodes 50–60 ms / 1,000 nodes 170–205 ms (real ELK Worker), flush as above. `bench/budgets/doc.json` still names `bench/doc.bench.ts` (WP-12's
  runner) as the measure; point it here or wrap these cases when the runner lands.
- **Write queue**: `editBlock` stamps outside the queue and enters it itself (call it outside `write()`); `flush`
  never enters the queue (flushes are serialized internally), so it can be reserved inside a slot (CONS-36);
  `load()` may run inside a slot (file reads only) and re-stamps imported cites in a later slot.
- **Events**: the store emits `doc.saved`, `doc.outline`, `doc.block.removed`, `doc.freshness`, `doc.claims`,
  `doc.proposal.removed`, `notice`. `doc.block.upsert` / `doc.proposal.upsert` carry rendered views, so the server
  emits them (from `ApplyResult` / the returned blocks).
- **Verdicts**: the store follows the core `Verdict` doc (L1 fail ⇒ `unsupported`, L1 vacuous ⇒ `cited`), which
  differs from gen spec §7.2 row 5.
- **ELK**: groups are laid out bottom-up (`SEPARATE_CHILDREN`); an edge between groups is an aggregated edge between
  the groups for layering and is drawn as a straight connector between the two boxes (`INCLUDE_CHILDREN` costs ≈ 10×:
  1,000 grouped nodes 1.6 s). Measured: 300 nodes 54 ms, 1,000 nodes 184 ms.
- **editBlock and UXP-20**: the store saves and returns `dropped`; the server's "出典が外れます" first step needs a
  preview — comparing `toMarkerForm` link groups with `claims(id)` by cite set gives the same answer.
