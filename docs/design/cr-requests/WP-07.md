# WP-07 — change requests (anchor + review engine, 2026-10-03)

## Anchor capture port for the synchronous `ReviewEngine.create` / `patch`
- contract: `packages/loop/src/contract.ts` — `LoopDeps` / `ReviewEngine.create(req: CreateThreadReq, …)`
- change: either add `captureAnchor(input: AnchorInput, previous: Anchor | null): { anchor: Anchor; aux?: … }` to
  `LoopDeps` (the shape `CapturedAnchor` in `packages/loop/src/review/engine.ts`), or let `create` / `patch` take an
  already stamped `Anchor` (+ aux) and move the `AnchorInput → Anchor` conversion into the server handler (server spec
  §8 already says handlers do "AnchorInput → Anchor は AnchorEngine で").
- why: `create` / `patch` are synchronous (they run inside the write slot) but stamping a code anchor needs the file text
  (`Indexer.currentText` is async) and a doc anchor needs `DocStore.blockText` + claim spans (§1.2). The review engine
  cannot do it itself without an async read inside the slot.
- workaround in place: `// CR-PENDING(WP-07)` on `ReviewEngineDeps.captureAnchor` (`packages/loop/src/review/engine.ts`);
  `createLoop` (WP-08b) / the server supply a sync port backed by text pre-loaded outside the slot.
- urgency: before WP-INT wires `POST /threads`.

## `ReviewEngine` extras the composer / server need
- contract: `packages/loop/src/contract.ts` — `ReviewEngine`
- change: add `status(): ReviewStatus` (`GET /review`), `waiters(): number`, `shutdown(): void` (daemon stop ⇒ every
  `wait` returns `shutdown` + `approved:false`), `snapshots(id): AnchorSnapshot[]` (outdated cards and
  `assembleAnchoredItems` need `spanLines` / `symStart`), `summary(id): ThreadSummary | null`.
- why: no contract method serves `GET /review`, the daemon idle logic needs the waiter count, the server needs a way to
  release long-polls at shutdown, and the server's re-anchoring input needs the capture-time snapshot.
- workaround in place: `ReviewEngineHandle extends ReviewEngine` returned by `createReviewEngine`
  (`packages/loop/src/review/engine.ts`); `createLoop` can expose it as `review`.
- urgency: before WP-INT wires the review routes.

## Finish(push) ↔ `JobRunner.create` dispatch rule
- contract: `packages/loop/src/contract.ts` — `JobRunner.create` doc comment (WP-08b)
- change: document "threads already `queued` with `batchRound = n` were dispatched by Finish; `create` fires T2 only for
  `open` threads".
- why: spec T2 is caused by both `POST /jobs` and `POST /review/finish`; without the rule a batch is dispatched twice
  (`E_STATE_TRANSITION`) or not at all.
- workaround in place: the review engine fires T2 (human) + sets `batchRound` before calling `create`, and reverts a
  partition with T4' (system) + a system message when `create` throws.
- urgency: before WP-08b lands `createLoop`.

## `mitori.review/1` overhead with long Japanese doc quotes
- contract: `REVIEW_STDOUT.quoteLabelChars` (40) vs `overheadTokensPerThread` (50)
- change: count the label quote in display width or cut non-ASCII quotes at ≈ 24 chars.
- why: at `CHARS_PER_TOKEN["claude-v5"].markdown_ja = 1.25`, a 40-char Japanese quote is ≈ 32 tokens by itself; with the
  rest of the heading a doc-anchored thread can reach ≈ 55 tokens. The golden round (quote of 21 chars) stays ≤ 50.
- workaround in place: none (the contract constant is used as is).
- urgency: nice to have (measure with real rounds first).
