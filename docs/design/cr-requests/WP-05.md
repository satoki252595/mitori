## A. Contract changes

## 1. A factory for the usage ledger
- contract: `packages/agent/src/contract.ts` — new export from `packages/agent/src/ledger/index.ts`
- change:
  ```ts
  export function createUsageLedger(deps: {
    db: SqlDb;            // state.sqlite (reads)
    stateWrite: WriteQueue; // the daemon-wide writer (every insert/upsert runs inside it) [CONS-03]
    random: Random;       // UsageRecordId
    clock: Clock;         // summary ranges (daemon-local days)
    log: Logger;          // price mismatch warnings (AGT-U-028)
  }): UsageLedger;
  ```
- why: `createAgentBridge(deps)` takes `ledger: UsageLedger`, `ServerHandle.ledger` exposes one and gen reads it, but no
  public function can construct it (server spec §3: "agent bridge（scheduler・ledger・engines）"). The implementation exists
  (`ledger/ledger.ts`, migrations = `AGENT_MIGRATIONS`), it just cannot be exported without an INDEX change.
- workaround in place: implementation in `packages/agent/src/ledger/ledger.ts`; tests/bench use `memLedger()` from
  `@mitori/agent/testing`. Export it from `ledger/index.ts` once accepted (one line).
- urgency: blocks WP-INT wiring of the bridge (M2).

## 2. Filesystem ports for the bridge (I3 system prompt files, I9 empty sandbox)
- contract: `packages/agent/src/bridge/index.ts` — `createAgentBridge(deps)`
- change: add `safeWrite: SafeWriter` (kind `home`: `run/sp/<sha256[:32]>.txt`, 0600, atomic; `run/empty/*` removal) and
  `fs: FsReader` (byte-compare before reuse [SEC-20], `readdir` of `~/.mitori/run/empty`). Optionally `fetch?` for
  anthropic-api (defaults to the global `fetch`).
- why: I3 requires writing a content-addressed system prompt file before every spawn and I9 requires checking/emptying the
  sandbox cwd; domain code may not touch `node:fs` and the deps have no SafeWriter/FsReader.
- workaround in place: `createAgentBridge` reads `safeWrite`/`fs`/`fetch` as optional extra properties
  (`bridge/index.ts`, `bridge/assemble.ts`); without them claude-cli/generic runs fail fast with `E_PRECONDITION` and a
  warning is logged once.
- urgency: blocks WP-INT (the integrator can pass the extra properties today; the type should say so).

## 3. `--session-id` when sessions persist (I4)
- contract: `BridgePaths` (agent contract B2)
- change: `sessionId?: string` — the uuidv4 mitori issues for `--session-id` when `engines.claude-cli.persistSessions` and
  `req.persistSession` (absent ⇒ `--no-session-persistence`, or `--resume <req.resume>`).
- why: `buildClaudeSpawn` is pure and has no `Random`; I4 says mitori issues the id.
- workaround in place: `claude/argv.ts` `ClaudeSpawnPaths = BridgePaths & { sessionId?: string }`; the engine passes it.
- urgency: nice to have (persistSessions is off by default).

## 4. A clock for the public normalizer
- contract: `createClaudeNormalizer(opts)`
- change: `opts.now?: () => UnixMs` (every `JobEvent` has `at`; the 1 Hz `usage(final:false)` throttle needs time).
- workaround in place: the engine uses the internal `createNormalizer(opts + now)`; the public factory stamps `at: 0`.
- urgency: nice to have (FakeEngine users see `at: 0`).

## 5. BP3 cache breakpoint on the user content (anthropic-api)
- contract: `AnthropicApiRequest.messages[].content[]`
- change: `{ type: "text"; text: string; cache_control?: { type: "ephemeral"; ttl?: "5m" | "1h" } }`
- why: gen spec §8.3 puts BP3 (shared DATA, 5m) on the first user block; the type has no `cache_control` there.
- workaround in place: `adapters/anthropic-request.ts` attaches it as an extra property (serialized as-is).
- urgency: nice to have (BP3 is used only when 2+ S8 calls share data).

## 6. The key of `UsageLedger.fixedOverhead(profileKey)`
- contract: `UsageLedger.fixedOverhead`
- change: define the key callers can compute: `xxh3("<engine>\n<mode>\n<model>\n<promptVer>")` (the bridge records a sample
  per clean first turn: first-call input − estimated user-message tokens), or replace the parameter with
  `{engine, mode, model, promptVer}`.
- why: the warm-profile key needs the pinned binary's realpath/version, which estimators (loop/gen) do not have.
- workaround in place: `bridge/assemble.ts` records with the key above (`CR-PENDING(WP-05) cr-requests #6`).
- urgency: nice to have (estimators fall back to the spec's initial values 0.8k / 1.4k / 4.5k).

## 7. Resuming a `window_spend` pause
- contract: `AgentScheduler`
- change: `resume(lane: Lane): void` (clears `window_spend` for the lane's current episode).
- why: UXP-08 pauses background when one run raised the 5h window by > `runWindowSpendPause`; gen's banner asks
  「続けますか？」 but the scheduler has no call to continue.
- workaround in place: the episode (and the pause) ends when the background lane drains — gen cancels its queued
  requests and resubmits after the confirmation.
- urgency: nice to have (M2, gen UX).

## 8. `WarmProfile` does not identify the launch (raised by the WP-05 verifier)
- contract: `WarmProfile` (agent contract B1, "the ONE definition" of the warm-profile key)
- change: add `launchHash: Xxh3` — xxh3 of the settings-derived launch (`--setting-sources` value, the env key/value set
  after scrub + ENV_INJECT), or state in the doc comment that a warm process also needs an identical launch.
- why: spec §6.6.1 keys warm processes by "every argv element but the prompt + the env key set", but the type carries
  only mode/model/effort/system/schema/ENV_INJECT hashes. A process warmed before the user switched on
  `inheritUserSettings` (user hooks then receive bundles, SEC-15) or changed `envPassthrough` matched the key.
- workaround in place: the claude-cli engine compares the warm process' SpawnSpec with the job's (argv with the
  `--max-budget-usd` / `--session-id` values masked, env, cwd, binary) and closes a stale warm process
  (`claude/profile.ts` `sameLaunch`).
- urgency: nice to have (warm pool is stretch, default 0).

## 9. A source for `kind:*` chars/token calibration
- contract: `UsageLedger` / `createAgentBridge` result
- change: `calibration(): CalibrationSnapshot` on the ledger (reads `use_calibration` `kind:<tokenizer>:<kind>`) and a
  writer for exact single-kind counts (`recordKindSample(tokenizer, kind, chars, tokens)`).
- why: core says "agent writes it, the indexer reads it" (CR idx-7) but no agent surface produces a
  `CalibrationSnapshot`; the producers (`count_tokens`, `mitori doctor --calibrate`) are out of WP-05's scope.
- workaround in place: none needed yet (the indexer uses factor 1.0 until a snapshot is wired).
- urgency: nice to have (M2 calibration window).

## B. Spec corrections from the contract tests (claude 2.1.288)

1. **SIGINT result has zero usage** (CC-16 / CT-09, AC-L37): after SIGINT the CLI emits `result` with
   `subtype: "error_during_execution"`, `terminal_reason: "aborted_streaming"`, `total_cost_usd: 0` and all-zero `usage`
   although ≈540 input + ≈750 thinking tokens were spent (`fixtures/agent-streams/sigint.jsonl`). Loop spec §6.5.2/§6.7
   ("SIGINT で出た result の usage は記録される") should read: an interrupted turn is ledgered from the meter
   (`usageEstimated: true`, outcome `cancelled`/`budget`); the normalizer maps `aborted_streaming` to `stop: "cancelled"`.
   The meter now also counts `system/thinking_tokens.estimated_tokens` (thinking is billed as output).
2. **init lists builtin plugins** (`plugins: [{path: "builtin"} …]`) even with `--setting-sources ""`. CC-03's
   "skills・plugins が空" must exempt `path: "builtin"`; I11 checks skills and MCP only (unchanged).
3. **normalizeForKey fence regex** (testing spec §3.3): `/<<<DATA [nonce]{8} /` matches gen's labelled fence only; loop's
   `UNTRUSTED_FENCE.open` is `<<<DATA {nonce}>>>`. The implementation matches both (`(?=[ >])`).
4. **`--json-schema` adds no API call**: one `message_start`, `stop_reason: "tool_use"` (StructuredOutput), `num_turns: 2`.
   Counting "an extra message_start in a turn" as a continuation (PT-09) is only safe after a `max_tokens` stop — that is
   what the normalizer does.
5. **Measured** (haiku 4.5): lean answer first-call input 585 tokens (≤ 1.0k), Read/Edit agent profile 3,731 (≤ 4.5k),
   2nd parked turn 1.19 s, `--max-budget-usd 0.0001` overshoot ≈ 32× (one response), `ephemeral_5m > 0` and `1h = 0`
   with `CLAUDE_CODE_PROMPT_CACHE_TTL=5m`. Sonnet CT-08 was not run (session cost cap $0.05).
