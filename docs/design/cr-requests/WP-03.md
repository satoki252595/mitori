Conventions of `ParseItemResult` this WP relies on (please keep them in the parse Worker):

1. **Go**: `headings[0] = {level: 0, line, text: <package clause name>}`; when the file has a `//go:build <expr>` constraint, add `{level: -1, line, text: <expr>}`. Files whose constraint is `ignore` are not members of their package (`resolve/context.ts` `goBuildIgnored`) — the fixture truth expands package imports to non-ignored files only.
2. **Rust**: `mod x;` → `ImportRecord {kind: "mod", spec: "x"}`; a preceding `#[path = "p"]` adds `names: ["path=p"]`. `use` trees keep the tree text in `spec` (`crate::a::{b, c as d}`); inline `mod x { … }` blocks must be `module` symbols with their line range (scopes `self::` / `super::` of the uses inside them).
3. **Python**: relative specs keep the dots (`..pkg`); `from a import b, c` → `names: ["b", "c"]`; `import a.b` → no names.
4. **Env template files** (`ENV_TEMPLATE_GLOBS`, CR idx-11 / m0-12) are excluded by S0 but must still be handed to the `env.files@1` detector (key names only).
5. Test names: either `ParseItemResult.tests` or `test.*@1` candidates; `linkFacts` de-duplicates (candidates win).

Schema: no change needed. Representative paths, the leaf/parent level of tombstones and the last clustering base (`path → blob`)
are kept in `idx_meta` (`structure.extra`, `structure.base`, `leiden_gamma`, `structure_version`).

## B. Spec / acceptance conflicts — please decide

### B1. m3e modularity ≥ 0.2 is not reachable on the specified graph (IDX-AT-31, MILESTONES WP-03)
- what: on `refs/m3e-canvas` (42 graph files, 166 collapsed import edges + IDF refs + directory prior) the best partition any
  Louvain run finds is **0.189** (best of 200 random visit orders, no size cap); simulated annealing tops out at 0.183. Our
  pipeline gives **0.163** (4 leaves of 3.8k–9.0k LOC), the directory partition **0.014** on the same graph. The research figure (0.262 vs −0.221,
  04 §2.5) was measured on a sparse name-reference graph (61 edges) without import resolution; every m3e file imports the same
  hubs (`lib/tokens.ts`, `lib/i18n.ts`, `components/ui.tsx`, `components/M3Node.tsx`), which caps modularity.
- proposal: keep "beats the directory partition" and replace the absolute floor by "≥ 0.9 × the best of 50 Louvain orders on the
  same graph" (bench-measured), or measure modularity on the reference graph the research used. Leiden refinement (M2) will not
  change the ceiling.
- re-verified by the WP-03 verifier: best of 300 random Louvain visit orders (γ = 1, no size cap, BFS split) on the same
  dependency graph = **0.191** (5–6 communities); the depth-2 directory partition of that graph = 0.014.
- in place: `structure/corpus.test.ts` asserts `modularity > dirModularity` and keeps the 0.2 floor as `test.todo` (CR-PENDING).
- crit: 0.423 (spec [仮] ≥ 0.45), directory partition 0.313. Other corpora (leaf partition / directory partition): hono 0.548 /
  0.232, fastapi 0.297 / −0.122, excalidraw 0.253 / 0.186, react 0.385 / 0.254, ripgrep 0.306 / 0.328 (crates are already
  ideal modules; the 2k–9k size rule splits them).

## C. Small deviations documented in code

- First clustering only (no previous leaves, no seeds): after the γ search (DirPartition start), the singleton start is tried at
  the chosen γ and wins when its modularity is higher without breaking the size rule (`cluster.ts` `fresh`); warm starts are never
  replaced (id stability).
- γ search steers on the pre-merge LOC-weighted median (monotone in γ); the spec's selection rule picks among the evaluated γ.
- Merging small leaves prefers partners that keep the merged leaf ≤ 4k, then ≤ 6k, then ≤ 9k LOC and never pushes the estimated sig
  skeleton over 24k tokens; an unchanged previous leaf that was already small is not merged again.
- Identity matching takes alive modules (Jaccard) before tombstones / seeds (representative hits) — mixing the two scores made
  two ids swap on every refresh.
- Seeded first scan (fresh machine, `doc.index.json` only): leaves are rebuilt from the seeds' reps + a neighbour vote
  (no clustering), so the committed chapters come back (IDX-AT-34 on crit: ≥ 95 % asserted, all leaves restored in practice).
- crit history replay (IDX-AT-33): 41 commits, worst 0 % ids lost per commit, 100 % survive (one commit, `a2c57795`, touches
  > 10 % of the graph files and re-clusters without losing an id).
- `entry.testmain@1` (`func TestMain(m *testing.M)`) is the one entry a test file emits (it cannot occur elsewhere): the fact
  keeps its file's `test` scope in `FactsResult.scopes`, so the main entry table never shows it (spec §5.1 vs §5.2).
- `modules[<prefix>].mergeInto` is applied to the clustering result (and carried by the next warm start) instead of
  contracting the files to one node before Louvain; the user's grouping wins over the size rule.
- A forced warm re-cluster of an unchanged snapshot is not a fixed point (crit: 9 of 13 leaves change a few members, every id
  survives; m3e 4 of 4; react adds one leaf): the post-processing (split / merge) result is not a Louvain local optimum and
  ε = 1e-4 rarely holds a node. Ids and slugs are stable (IDX-AT-33 worst 0 %), and 20 forced re-clusters after random body
  edits all equal the first forced one. Proposal: tune `STRUCTURE_PARAMS.hysteresis` with the §11.4 replay (contract value).
- Seeds are untrusted (`doc.index.json`): ids failing `isId("module")` and duplicates are dropped (`notice.seed.dropped`), a
  slug another seed holds is re-slugged, and a seed restore that would grow a leaf past the hard cap clusters instead.
- Goldens (`fixtures/golden/<fixture>/indexer/*`, `repo-pack.txt`) are not frozen yet: the S2–S4 tests run on a test-only stand-in
  for WP-02's parser (`structure/test/corpus.ts`); freezing them before the real parse Worker lands would bake in its symbol rules.
