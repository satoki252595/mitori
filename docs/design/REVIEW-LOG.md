# REVIEW-LOG.md — 敵対的レビュー（R1）の指摘と解決

- 版: R1（2026-10-03） / 所有: lead architect / 対象: `ARCHITECTURE.md`・`MILESTONES.md`・`adr/`・`contracts/*.ts`・`specs/*.md`
- 入力: `reviews/consistency.md`（CONS）、`reviews/security.md`（SEC）、`reviews/perf-tokens.md`（PT）、`reviews/ux-personas.md`（UXP）、`reviews/scope.md`（SC）。計 **143 件**（critical 6、high 47、medium 62、low 28）。
- 方針: critical / high は全件修正（反証できたものは理由を書く）、medium は安いものを修正。**却下は 0 件**。一部は「採用・形を変更（accepted-modified）」または「延期（deferred: 目標 M と理由）」。
- 検証: 7 契約（core / api / indexer / gen / loop / ui / server）を `nix develop --command bunx tsc@6.0.3 -p docs/design/contracts/tsconfig.json`（strict + `exactOptionalPropertyTypes` + `noUncheckedIndexedAccess` + `noUnused*`）で **0 エラー**（`contracts/testing.md` 付録 A の testkit 型宣言を足した 8 ファイルでも 0 エラー）。新しい正規表現・テンプレート寸法は `bun` で実行確認（`AGENT_PATH_ALLOWED_RE` の許可/拒否 23 例、SKILL.md 1,512 B ≤ 1,536 B、prep README 1,205 B、`HREFS` の出力、`SETTING_SCOPES_CHECK = [true,true,true]`）。
- **優先順位（本パス以降の正本規則）**: (1) `contracts/*.ts`（型と定数）、(2) 本書の「変更内容」列（規範的な修正。spec 本文が未改訂でもこちらが勝つ）、(3) `ARCHITECTURE.md` と ADR、(4) 各 spec 本文。各 spec の冒頭に「改訂 R1」節を置き、本書の該当 ID への参照で上書き箇所を列挙した（SC-17）。
