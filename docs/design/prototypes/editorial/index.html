3.1レビューの1往復

エージェントはcritをバックグラウンドで実行する。CLIはカレントディレクトリとブランチからセッションキー（sha256(cwd + "\0" + branch)の先頭12文字）を計算し、同じキーのデーモンが生きていればそこに繋ぎ、いなければ新しく起動する。

やさしく · 初めての人向けの言い換え · 0.4k tok · キャッシュ済作業場所ごとに番号札を作って、同じ番号の係（デーモン）がいればその係に頼み、いなければ新しく係を呼ぶ、というイメージです。

デーモンは準備が整うまで、セッションに依存するAPIへ503を返す。CLIは/api/sessionを500ミリ秒ごとに問い合わせ、5分たっても503なら諦める。

準備が整うと、CLIはPOST /api/review-cycleを送り、人がFinishを押すまで応答を待ち続ける。HTTPのタイムアウトは24時間ある。応答のpromptはstdoutへ、approvedはstderrへ出るので、エージェントはstdoutを読んで修正に取りかかる。

修正を終えたエージェントは、stdoutの末尾にあるnext_commandを実行する。2回目以降のreview-cycleは、待ち始める前にラウンドの完了を知らせるので、ブラウザは差分を取り直す。

落とし穴

接続が切れたことを「承認」と取り違えない。デーモンがFinishの前に止まると、review-cycleはapproved: falseを明示した503を返す。エージェント側でも、応答が無いことを承認とみなしてはいけない。

なぜ待ち合わせを、ブロッキングするCLIにしたのか

シェルコマンドを1つ実行できるエージェントなら、どれでも同じ手順で参加できるから推測と考えられる。critはMCPサーバを持たず、15種類のツールにはskillとhookだけを配っている。

動機はコードに書かれていません。READMEかcommitで裏付けが取れれば「確認済」にできます。

DEEP DIVEFinishを取りこぼさない順序L3 · 約1分

review-cycleは、ラウンド完了の通知（SignalRoundComplete）より先に購読（Subscribe）を始める。順序が逆だと、通知してから購読するまでの短い間に人がFinishを押したとき、そのfinishイベントを受け取れず、CLIは24時間待ち続けることになる。

コメントの書き込みは200ミリ秒のdebounceでまとめ、temp→fsync→renameの順で原子的に置き換える。

3.2storyの生成（ターミナル経路）

crit storyは、差分の全文を一時ファイルに書き出し、プロンプトにはそのパスだけを渡す。差分の大きさには、意図して上限を設けていない。実行するのはglobal設定のagent_cmdだけで、未設定ならエラーで止まる。

generateStoryは、エージェントの出力がJSONとして読めないとき、パースエラーを添えて正確に1回だけ再試行する。2回目も失敗すると、生の出力を一時ファイルに保存してexit 1で終わる。各回は5分で打ち切られる。

戻ってきたstoryはstory.Runで検証する。順序は固定で、①指紋の不一致（drift）、②同じhunkの重複、③配置率50%未満、のどれかなら保存を拒む。それ以外の欠落はsupportへ自動で補い、ok:falseとして保存する。

ただし推奨経路の--story-fileでは指紋が刻印されないため、①は実際には働かない推測。指紋を書き込むのは--skip-llmの経路だけに見える。

まとめ

  • 待ち合わせはHTTPのlong-poll 1本。stdoutが次の指示、stderrが承認の有無。
  • 壊れたJSONは1回だけ救う。それでもだめなら生の出力を残して止まる。
  • 検証と修復はエージェントではなく、crit側の決定的なコードが行う。

6.3internal/session — コメントの持ち越し

ラウンドが変わると、未解決のコメントは新しい本文の対応する行へ持ち越し（carry-forward）される。まず旧本文と新本文の行diffをHirschberg法で取り、旧い行番号から新しい行番号への対応表を作る。コメントの開始行と終了行はこの表で写し、範囲外は1〜最終行に丸める。

写した位置の行が、コメントを付けたときの行テキスト（アンカー）と一致しなければ、「近い形」かどうかを判定し、だめならファイル全体からアンカーを探す。どこにも無ければdriftedの印を付け、位置はLCSのまま残す。コメントは消さない。

DEEP DIVE「近い形」の判定L3 · 約1分

前後の空白を除いて一致する、短い方が8文字以上で長い方に含まれるか真ん中の1か所を削った形になっている、Levenshtein比が0.7以上、のいずれかなら同じ行とみなす。8文字の下限は、}やreturn nilのような短い行が、どんな長い行にも一致してしまうのを防ぐためだと、コードのコメントに書かれている。

計測行diffはO(N·M)。1k行で2.8ms、10k行で258ms（go test -bench、2026-10-02）。大きな計画を持ち越すたびに積み上がる。
