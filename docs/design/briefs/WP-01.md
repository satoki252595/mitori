## What platform is (M0)

`@mitori/platform` has **no contract file of its own**: it implements the ports declared in core §18 (`Logger`,
`Clock`, `Hasher`, `SqlDb` + `Migration`, `GitReader`, `FsReader`, `SafeWriter`, `Random`, `Metrics`,
`WorkerPool`, `WriteQueue` shape), the server-only ports of `packages/server/src/contract.ts` §2 (`FsWatcher`,
`WATCH_BATCH`, `DOC_WATCH_IGNORE`, `resolveSafePath`) and `Spawner`/`SpawnSpec`/`ChildHandle` (agent contract
B4). Read the agent contract only for B4 (`Spawner` and the spawn spec) — the rest is context.

- platform may import **only `@mitori/core`**. For shapes defined in other packages (`FsChange` in
  `@mitori/indexer`, `Spawner` in `@mitori/agent`, `FsWatcher` in `@mitori/server`) declare structurally identical
  local types; WP-INT's `compose.ts` assigns your objects to the contract types, which type-checks the match.
- Factory names are yours (e.g. `createSqlDb`, `createHasher`, `createSpawner`, `createSafeWriter`,
  `createGitReader`, `createFsWatcher`, `createWorkerPool`, `createLogger`, `systemClock`, `cryptoRandom`).
  Export them from the planned sub-directories (`sqlite`, `hash`, `spawn`, `worker`, `watch`, `fs`, `lock`, `log`,
  `random`, `clock`, `metrics`, `git`) — `src/index.ts` already re-exports each one.
- `resolveSafePath` is a stub in `spawn/index.ts`; `@mitori/server` re-exports it, so keep the exact signature.
- `src/testing.ts` (`@mitori/platform/testing`) should provide `memDb`, `memGitReader`, `createFakeSpawner`,
  `inlineWorkerPool`, `createFakeClock`, `createTestLogger` with the shapes in the testkit contract §1–§2; the testkit
  currently has stubs for them (`packages/testkit/src/ports/`) and will re-export yours (CR m0-6).
- Platform is the only place allowed to call `writeFile`/`rename`/`mkdir`, `Bun.spawn`, `crypto.getRandomValues`,
  `Date.now`; everything else gets them through these ports (the boundary checker enforces it).
- Node adapter is out of scope (MILESTONES §11) — keep Bun specifics behind the ports anyway.
- O3 (Linux watcher) measurement + decision goes to `docs/design/specs/platform-watch.md` (explicitly allowed by
  the acceptance test).

## How to work (every WP)

- **Write only inside 所有** (MILESTONES §1.2 is the authority). Shared things are pre-split: budgets per package (`bench/budgets/<pkg>.json`), i18n per namespace, fixtures per WP (add-only). Every package's `src/index.ts` is integrator-only and already re-exports every planned sub-directory — so export public names from **your sub-directory's `index.ts`**, and only contract names (helpers stay in sibling files; intra-package imports are relative).
- **Contract gaps**: never edit `packages/core` or another owner's code. Write the request to `docs/design/cr-requests/<WP-id>.md` (what / why / proposed shape) and use a clearly marked local workaround (`// CR-PENDING(<WP-id>): …`). The architect batches requests weekly into `packages/core/CR-LEDGER.md` (48 h SLA).
- **Depend on contracts, not on other WPs**. The shared fakes (`@mitori/platform/testing`, `@mitori/agent/testing`, `@mitori/testkit`) are themselves M0 stubs until WP-01 / WP-05 / WP-00b+WP-12 land: write the minimal fake you need in your own test files (a `Hasher` over `Bun.hash`, a `Random` over fixed bytes, `bun:sqlite` `:memory:` for `SqlDb`, an in-thread `WorkerPool`) and switch when the shared ones exist.
- **Boundaries** (`scripts/check-boundaries.ts`, part of `check`): imports follow `PACKAGE_DEPS` (type-only too; only `@mitori/core` types are free); no deep imports (`@mitori/x/src/…`) and no `../` out of your package; `Bun.*` / `bun:*` / `node:*` / `process.*` only in platform, server, cli; direct `writeFile`/`rename`/`mkdir`/spawn/`Bun.write`/`Bun.spawn`, `crypto.getRandomValues`, `Math.random`, `Date.now` only in platform — use the SafeWriter / Spawner / Random / Clock ports; `@mitori/testkit` and `@mitori/<pkg>/testing` only from tests (`*.test.ts`, `test/`, `src/testing.ts`, bench, eval, e2e).
- **Commands** (always via `scripts/nd`): `scripts/nd bun run check` (tsc -b, biome, boundaries, CR ledger, budgets lint, contract index, svelte-check — parallel, ≈ 1 s at M0), `scripts/nd bun test <path>`, `scripts/nd bun run fmt`. Tests sit next to the code (`foo.test.ts`) or under `packages/<pkg>/test/{unit,golden,int}/`; put the spec ID first in the name (`describe("IDX-AT-12 …")`). Unit test files stay ≤ 500 ms.
- **Public surface** changes show up in `docs/design/briefs/INDEX.md` (`bun run contract:index`; `check` fails when it is stale). An INDEX diff in your PR = a contract change → CR.
- **Done** = the acceptance tests in §1 pass with the exact commands, `check` is green, commits are conventional and end with the Co-Authored-By line; never push, never rewrite history, no paid LLM calls unless the WP says so.
