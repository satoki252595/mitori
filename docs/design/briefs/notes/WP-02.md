## Notes (M0 layout)

- **Facade**: `createIndexer` and `INDEXER_MIGRATIONS` are stubs in `update/index.ts` (yours). The facade composes
  S0–S1 (yours) with S2–S4 + search (WP-03, parallel). Agree with WP-03 on *internal* stage functions living in
  their sub-directories (e.g. `structure/stage.ts`, imported relatively — not exported from their `index.ts`);
  test the facade with `ScanOptions.until: "S1"` until WP-03 lands.
- **Migration**: `INDEXER_MIGRATIONS` version 1 = the whole `idx@1` schema of spec §9, including the tables WP-03
  fills (FTS5, modules, graph); WP-03 sends schema changes to you.
- `CodeSlice`, `IndexDelta`, `SymbolChange` now live in core §20 (CR m0-1) and are re-exported by the indexer —
  import them from `@mitori/core` inside the package.
- Domain package: no `Bun.*`/`node:*`. Read files through `FsReader`, git through `GitReader`, hash through
  `Hasher` (deps). The parse Worker must not use Bun APIs either (`createParseWorker(env, init)`; its entry file is
  server/WP-INT's). Tests may use `node:fs`/`Bun.file` to load the pinned wasm:
  `node_modules/web-tree-sitter/web-tree-sitter.wasm`, `node_modules/tree-sitter-{typescript,javascript,python,go,rust}/*.wasm`.
- Stubs at M0: `classifyByPath`, `computeIndexDigest` (inventory), `createParseWorker`, `poolSize` (parse),
  `countCjk`, `estimateTokensRaw` (tokens), `createIndexer`, `INDEXER_MIGRATIONS` (update). `moduleIdFor`/`slugify`
  are WP-03's (structure).
- Pin store (`idx_blob_text`, `pinBlobs/unpinBlobs`, 7-day GC) and `symbolsAt(blob)` are cross-spec requests from
  loop (`loop→idx-1/2`); `symbolsAt` is not in the contract yet — add it via a CR request (it is "型は WP-02 で追加").
