## Golden / truth / fixtures

- PT-01 SSE fuzz byte-identity, SRV-I-001…032 and SRV-AT-01…10 (testing spec §4.5). The in-process server harness
  (`startTestServer`) is a testkit stub today — start your own in-process server in tests.

## Notes (M0 layout)

- The DTO sections of `packages/core/src/api.ts` (§1–§8) are reference: read the ones your routes touch. §0
  transport, §9 route table (`ROUTE_META`), §10 SSE events, §11 daemon registry are the must-reads.
- Stubs: `decideVersionAction` (http/), `DEFAULT_GLOBAL_SETTINGS`, `resolveSettings`, `checkSettingsPatch`
  (settings/), `buildInbox` (inbox/), `resolveDocId` (ws/). `createServer` (compose.ts) and
  `assembleAnchoredItems` / `distributeReanchor` (wiring/) are WP-INT's. `resolveSafePath` is implemented by
  platform (WP-01) and re-exported from the server contract.
- server may use `Bun.*` (`Bun.serve`) and `node:*`, but never write files or spawn directly — `SafeWriter` /
  `Spawner` ports only (boundary checker).
- `@mitori/client` (`packages/client/src/{http,sse}/`): typed `call(routeKey, …)` over `ROUTE_META` and a fetch-
  stream SSE client; it may import only core (it ships in the web bundle).
- Unimplemented routes answer 501 (`E_UNSUPPORTED`) — that is exactly what M0 stubs throw; map `MitoriError.http`.

## CR batch 1 (2026-10-03)

- **CR m0-10**: `@mitori/client` now has its own contract `packages/client/src/contract.ts` (`ApiClient`,
  `SseClient`, `ConnectionState`, `EntityKey` moved from the web contract; `ClientAuth`, `ClientOptions`,
  `SseClientOptions`). Implement the stubs `createApiClient` (`http/index.ts`) and `createSseClient`
  (`sse/index.ts`). `ApiClient.call` args gained `onRev?(rev)` (called with `x-mitori-rev` before resolving).
  Backoff jitter uses the injected `Random`, `live.since` the injected `Clock` (client is not entropy-exempt).

  taken by the composition root with platform `acquireLock` — replace `LockFilePort` in `startDaemon` with a held lock
