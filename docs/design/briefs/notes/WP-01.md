## What platform is (M0)

`@mitori/platform` has **no contract file of its own**: it implements the ports declared in core §18 (`Logger`,
`Clock`, `Hasher`, `SqlDb` + `Migration`, `GitReader`, `FsReader`, `SafeWriter`, `Random`, `Metrics`,
`WorkerPool`, `WriteQueue` shape), the server-only ports of `packages/server/src/contract.ts` §2 (`FsWatcher`,
`WATCH_BATCH`, `DOC_WATCH_IGNORE`, `resolveSafePath`) and `Spawner`/`SpawnSpec`/`ChildHandle` (agent contract
B4). Read the agent contract only for B4 (`Spawner` and the spawn spec) — the rest is context.

- platform may import **only `@mitori/core`**. For shapes defined in other packages (`FsChange` in
  `@mitori/indexer`, `Spawner` in `@mitori/agent`, `FsWatcher` in `@mitori/server`) declare structurally identical
  local types; WP-INT's `compose.ts` assigns your objects to the contract types, which type-checks the match.
- Factory names are yours (e.g. `createSqlDb`, `createHasher`, `createSpawner`, `createSafeWriter`,
  `createGitReader`, `createFsWatcher`, `createWorkerPool`, `createLogger`, `systemClock`, `cryptoRandom`).
  Export them from the planned sub-directories (`sqlite`, `hash`, `spawn`, `worker`, `watch`, `fs`, `lock`, `log`,
  `random`, `clock`, `metrics`, `git`) — `src/index.ts` already re-exports each one.
- `resolveSafePath` is a stub in `spawn/index.ts`; `@mitori/server` re-exports it, so keep the exact signature.
- `src/testing.ts` (`@mitori/platform/testing`) should provide `memDb`, `memGitReader`, `createFakeSpawner`,
  `inlineWorkerPool`, `createFakeClock`, `createTestLogger` with the shapes in the testkit contract §1–§2; the testkit
  currently has stubs for them (`packages/testkit/src/ports/`) and will re-export yours (CR m0-6).
- Platform is the only place allowed to call `writeFile`/`rename`/`mkdir`, `Bun.spawn`, `crypto.getRandomValues`,
  `Date.now`; everything else gets them through these ports (the boundary checker enforces it).
- Node adapter is out of scope (MILESTONES §11) — keep Bun specifics behind the ports anyway.
- O3 (Linux watcher) measurement + decision goes to `docs/design/specs/platform-watch.md` (explicitly allowed by
  the acceptance test).

## CR batch 2 (2026-10-03, ledger §5) — follow-ups owned here

- `GitReader.checkIgnore?`, `remoteUrl?`, `headMeta?` are in core (optional until you implement them; required next
  batch) — CR m1-25, m1-26. `remoteUrl` strips `user:pass@` and never contacts the remote; `headMeta` = HEAD committer
  date (merges included) + `git describe --tags --abbrev=0`.
- New platform functions: `hardwareInfo(): HardwareInfo` (sync, `sysctl -n hw.perflevel0.logicalcpu` once; type now in
  core) — CR m1-116; `detectGateSandbox(): "sandbox-exec" | "bwrap" | "none"` — CR m1-119. The CLI passes both into
  `ServerDeps` (WP-11).
- `SAFE_WRITE_RULES`: kind `doc` / `prep` create a missing `rootReal` when its existing parent chain is a realpath
  (CR m1-45; WP-INT then removes `docRootWriter`); kind `prep` writes `fingerprint` 0600 (CR m1-21).
- Add `bench/budgets/platform.json` (CR m1-113) and run `budgets:merge`. darwin RSS budgets are measured as
  `phys_footprint` (CR m1-117).
