# M1 integration report (WP-INT, 2026-10-03)

All eleven WP branches (01, 02, 03, 04, 05, 06, 07, 08a, 09, 10a, 12) are merged into `main` with `--no-ff`, the
composition root is implemented, and the compiled binary opens real repositories and shows the zero-token design doc
in Chrome. `bun run check` is green; `bun test` passes 2,143 tests (0 failures, 4 skipped). Measured on an Apple
M5 Max (darwin-arm64) while other agents were running. Linux was not measured.

## 1. What works end-to-end

- **`mitori <path>` / `mitori _serve`** (binary 68.8 MB) runs the daemon built by `createServer`
  (`packages/server/src/compose.ts`). It takes the daemon lock, opens the state DB with every package's migrations,
  creates the agent bridge and usage ledger, builds the Worker pools (parse, Shiki, ELK) and serves the shell. With a
  path, it opens the workspace in-process and prints the counts and a login URL. A second `mitori` on the same home
  uses the daemon that is already running.
- **Open → S0–S4 → zero-token doc**: the real indexer runs, with WP-03's S2–S4 wired behind WP-02's facade
  (`packages/indexer/src/update/later.ts`) and the tier-1 fact detectors compiled into the parse Worker. Then
  `applyStatic` builds the static doc, with a container map built from the module graph. The doc flushes to
  `.mitori/` (or to `~/.mitori/repos/<ws>/doc` for directories without git, which get a shadow git repo).
- **Browser (Chrome, 1440×900)**: header, TOC, map (ELK container), the "generate" card, the static-facts tiles,
  the Reader for the static sections (§4, §5, §6, §8, §11, appendix), and the ⌘K palette (sections, rooms, files,
  symbols, terms). Light and dark themes both work.
- **Live updates**: file save → watcher → `indexer.update` → `index.changed`. Claims and threads are re-anchored in
  one pass. `setClaimChecks` and `setFreshness` run in the same slot (one `rev`), and `doc.freshness` follows. Pins
  move from old to new blobs. The static doc is re-applied and `map.updated` sent. `palette.changed` names the source
  group that changed. Edits in the doc directory → `doc.load()`.
- **Generation (M2 path)**: estimate → `POST /gen/runs` → the real claude-cli engine, normalizer, scheduler and
  ledger, driven by a scenario `claude` (test spawner, 0 tokens) → `doc.block.partial` / `doc.block.upsert` SSE
  (the server renders `BlockView`s for the blocks gen writes) → flush. After `POST /init {commit:true}` (which sets
  `.gitattributes` and `.mitori/.gitignore`), the committed Markdown carries relative cite links that resolve to the
  cited lines. The session engine works end to end: prep → `out/*.ndjson` → `check` → `ingest` → `NEXT`.
- **Module identity**: a committed `doc.index.json` with foreign ids, opened in a fresh home, brings back 13 of 13
  leaf ids on crit.

## 4. Failing / remaining per WP

- **WP-01 platform**: Linux O3 watcher numbers not re-verified (no Linux runner); testkit re-export of
  `@mitori/platform/testing` pending (S10); no polling fallback when inotify runs out; the SEC-05 fixes to mirror on
  the write side (WP-08b). New: no `hardwareInfo()`; the darwin RSS-vs-footprint measurement note.
- **WP-02 indexer A**: gostd cold 2.0 s (limit 1.5 s) and peak RSS ≈ 1.05 GB (limit 1 GB) fail; crit cold and warm
  miss their targets but stay within limits. `bun run bench --filter idx.s01` still needs WP-12's runner. New from
  integration: the `add` event for an existing path loses `oldBlob` (stale badge needs a second update). The parse
  Worker entry now lives in `packages/server/src/workers/parse.ts`, with a GC every 256 KiB.
- **WP-03 indexer B**: m3e modularity ≥ 0.2 is still a todo (CR B1); fixture module constraints (B2); route mounts
  (B3); goldens not frozen. The stage functions now run behind the facade. Module/repo skeletons and `moduleContext`
  are minimal integrator versions (CR WP-INT §C); S2 is not incremental.
- **WP-04 doc**: sidecar sharding decision (R1-O6); ELK on dense graphs; `stampRun` and the renderer diagram dims are
  pending; no `mdLine` (the server derives it); `editBlock` keeps `stale` freshness. The SafeWriter doc root is
  created by the composition root.
- **WP-05 agent**: paid contract cases not re-run; WarmProfile launch identity (#8); `kind:*` calibration (#9). New:
  no first-run pinning, so the engine card says "not found" on a fresh install.
- **WP-06 gen**: WP-06b entry points (`onIndexDelta`, expand, simplify, translate, syncBlocks) are still
  E_UNSUPPORTED, so `publishSuggestions` is wired but publishes nothing yet. R3/R5 are applied provisionally. Gen keeps

- **WP-08a bundle/router**: `bench/loop.bench.ts#bundle:M` is unwritten; the ACCEPT/DENY lines of pull bundles are an
  architect decision; WP-08b must build `BundleBuilderDeps` from the DocStore.
- **WP-09 server**: SRV-I-014 (403 on `.git/config` / `.env`), SRV-I-020/026 and SRV-AT-08 can now run against the
  composed daemon but are still written for WP-09's fake domain. `srv.rss.idleLoaded` and the shell-paint bench files
  do not exist (measured here instead). No `SettingsView.lastError`.
- **WP-10a web**: initial JS 83–84 KB gz (warning); e2e/size commands still need WP-12's harness and WP-11a's binary
  (the binary now exists); `mitori:facts:painted` is not emitted. The API/SSE clients are local fallbacks until

## 5. Visual gaps vs `docs/design/prototypes/editorial/shots/`

Screenshots are in `docs/progress/m1/` (crit): `-01` first screen (light), `-02` dark, `-03` / `-03b` Reader (§4,
§8), `-04` ⌘K, `-05` / `-05b` fake-engine generation in progress. Compared with `01-first-run-map`, `01c-generating`,
`02-reader-standard`, `05-palette-romaji` and `06b-map-dark`:

1. **Map**: the prototype's floor plan (zones with LOC, file chips, doors, actors such as "ブラウザ（人）") is WP-18
   (stretch). The MVP ELK container shows small rooms with clipped labels ("internal/se…") and several empty boxes at
   the fit-to-view zoom. The provisional module names ("internal + cmd · CritJSON") read worse than the prototype's
   labels until gen's `labels` prompt runs. A banner "間取り図にできない構成のため依存図で表示しています" shows on
   every repo, because the floor plan is never enabled.
2. **Hero**: the prototype has the remote and language-version line, license and commit date, the README quote and
   stat tiles (lines per area). Ours shows only "go · 64.9k LOC · 1,219 files · 406875d"; the README quote and the
   tiles are missing (`WorkspaceStatus` has no license or commit date, CR from WP-10a).
3. **Generate card**: on a fresh machine it says "claude-cli · 見つかりません" (no pinning flow, §4 WP-05) instead of
   the three effort tiles with estimates and the 生成 button. With the scenario engine the tiles render, but 完全
   equals 標準 (≈94.7k tok): `complete` effort is not differentiated yet (WP-06 P3).
4. **Generation in progress**: the card has 入力 / 出力 / API 換算 / 経過 and pause / cancel. The prototype's stage list
   (repo pack fixed, overview §0–§2, §3, module chapters n/14 with a progress bar) and the "60倍速" timeline are
   missing. Input shows 0 / ≈0.43M during the run. A toast "§0 ひとことでが届きました · 最初の文まで 2.2 秒" works.
5. **Header**: no "today $ · tok · 5h %" usage block and no version tag next to the commit (prototype:
   `406875d · v0.21.1`).
6. **30分コース card**: "生成すると使えます" before generation, where the prototype shows "0 / 7 · 残り約30分".
7. **Reader (static sections)**: the section title appears twice (the page header and the doc's own

11. Fixed during integration: the "画面（vdev）と daemon（v0.0.0）の版が違います" reload banner that showed on every

## 6. Contract CRs collected

All of them, with shapes, are in `docs/design/cr-requests/WP-INT.md`. In brief:

- **Ratify or revert four provisional re-exports**: gen `createPromptRenderer`, agent `createUsageLedger`, doc
  `createHighlight` and `elkLayout`.
- **`ServerDeps`**: version, pid, userHome, port, gateSandbox; a lock port, or an acquired lock for `startDaemon`.
  `createServer` on a held lock → `E_CONFLICT`.
- **Reanchor helpers**: `distributeReanchor` / `assembleAnchoredItems` need the stored claim checks and the full
  thread anchor (or partial outputs).
- **`ServerHandle.render`** is per workspace; `pools.parse` needs the object format; `WorkspaceManager.update` for
  init.
- **gen**: Verifier, `idle()`, `fs`, a run list, and the post-pause writes bug.
- **indexer**: owners for module/repo skeletons and `moduleContext`; incremental S2; the editor-save `add` event.
- **doc**: `editBlock` freshness; `mdLine`.
- **agent**: first-run claude pinning.
- **platform**: `hardwareInfo()`; macOS footprint for RSS budgets.
- **web**: emit `mitori:facts:painted`.
