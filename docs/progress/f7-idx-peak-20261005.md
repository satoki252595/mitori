# F7 indexer peak RSS の根因修正（2026-10-05）

React pinned commit `7c6ac13e19fef500b7f669a16bbd01ecc95965ca` の cold scan を既存 idx-only benchmark で測定した。RSS は `process.memoryUsage().rss` を **10 ms ごと**に採取し、worker thread を含む process peak、MB は 2²⁰ bytes とする。CR m1-117 の Darwin `phys_footprint` は idle 用であり、ここへ流用していない。target **700 MB** / limit **1000 MB**、worker fixed cap、timeout、解析対象を変更していない。

## 根因と実装

1. **既存 OS hardware policy の未配線。** CR m1-116 の `hardwareInfo()` が未実装で、production CLI と bench がともに `perfCores: null` を渡していた。この Mac の OS 最高性能 tier（`hw.perflevel0.name=Super`）は **6 logical cores**、次の tier（`hw.perflevel1.name=Performance`）は **12 logical cores** と OS が返す。既存 policy は `hw.perflevel0.logicalcpu` の **6** を使うが、fallback は worker **8** だった。platform helper と CLI / bench を配線し、既存 `poolSize()` のまま worker **6** にした。非 Darwin、失敗、未知・不正値では既存 null fallback を維持する。固定 cap を減らしたのではない。
2. **既存 shared WASM port の production 未配線。** worker 側と test pool は compiled module を扱うが、production parse init と bench は raw bytes だけを送り、各 worker が runtime / grammar を compile した。既存 test helper を `withPrecompiled` として共用し、pool thread で一度 compile してから worker へ渡す。compile / clone が使えない環境は raw bytes の既存 loader へ戻す。runtime の instantiate failure も既存 bytes fallback を維持する。
3. **WASM fallback closure の保持。** runtime fallback が init 全体を capture して grammar byte map も保持していた。runtime bytes だけを capture するようにして、loaded grammar bytes を捨てる既存処理が init に阻まれないようにした。

CLI の許可済み依存に合わせ、indexer helper は server の public barrel から re-export する。deep import と PACKAGE_DEPS を緩めていない。CR m1-116 の適用と CR perf-1 は core ledger、公開名は contract index に記録した。UI renderer / Windows spawn / assets の並行変更を保持した。
