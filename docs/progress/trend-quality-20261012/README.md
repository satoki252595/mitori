### 文章の質（読んだ所感）

- 良い点: 事実ごとに出典があり、§0〜§2 は短く正確。モジュール章は「変更の手引き」（影響先・テスト・よく使われる宣言・一緒に変わるファイル）が具体的。
- 弱い点: モジュール章の「公開インターフェース」「データ構造」は識別子の列挙に寄り、初見者には硬い（例:「部分観測の容器を作る」）。巨大ファイルの「中身」節はシンボルの羅列。

## 残課題

- rea の §3: 差分再生成では既存の流れの題名が残る。候補から外れた既存の流れを入力から外すか、削除提案にする必要がある（新規生成では修正 7 が効く）。
- 書き出し HTML がコード抜粋込みで 10〜12 MB（抜粋 1,900〜2,400 件）、抜粋なしでも 4〜4.5 MB。共有用には大きい。
- Muse の費用記録（バイト推計）と見積り（トークン）の単位差で、記録が見積りの約2倍に見える。
- Codex 引用の追加2生成・Grok Build の実生成は、提供元の利用上限・残高が戻ってから。
