# モジュール章の読みやすさ（WP19、2026-10-13 後半）

[trend-quality-20261012](README.md) の所感で挙がった弱い点への対応。指示文は `gen.module@12`・`gen.parent@4` に上げた（`70a2409`）。ほかの指示文は不変なので、ほかの章のキャッシュは効いたまま。

## 背景（弱い点の所感）

- モジュール章の「公開インターフェース」「データ構造」は識別子の列挙に寄り、初見者には硬い（例:「部分観測の容器を作る」）。
- 巨大ファイルの「中身」節はシンボルの羅列で、本文の前に置かれていた。

## 変えたこと

- interface は「呼び出す側が何のために来るか」の1文から始め、重要な入口だけを動詞句で6項目まで書く。対の記号は1項目にまとめ、補助関数と名前の直訳は書かない。
- data は「何を表し、誰が作り誰が読むか」と必要なフィールドだけ書く。
- 初出の用語は言い換える。名詞の「と」3連は書かない。中国語の語（目录・快照）ではなくカタカナ語を使う。
- 静的ブロック「大きなファイルの中身（1,500 行を超えるファイル）」は本文の前から本文の後（深掘りの後）へ移した。

## 過去分の扱い

利用者の判断「改善してよい。過去分はすべて作り直さなくてよい」による。

- 鮮度（stale）と差分再生成の提案（S9）は prompt の版に依存しない。このため既存の文書を開いても「要再生成」にならず、コードが変わったモジュールだけが新しい指示文で作り直される。回帰テストは `packages/gen/src/incremental/rules.test.ts` の WP-19 の2件。
- 利用者が明示的に再生成した章は新しい指示文になる。
- 既存の文書の「大きなファイルの中身」の位置は、その章が作り直されるまで変わらない。
